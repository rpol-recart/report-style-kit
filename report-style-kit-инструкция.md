# Инструкция: генерация квартального отчёта в стиле образца (report-style-kit)

Пошаговое руководство для агента/оператора в закрытом контуре. Комплект создаёт готовый отчёт (.docx + .pdf), сохраняющий шрифты, оформление, стиль изложения и доменную лексику образца прошлого квартала.

**Принцип:** модель решает ЧТО написано, скрипты гарантируют КАК это выглядит. Не редактируйте docx руками и не обходите линт.

---

## 0. Пререквизиты (проверить до старта)

| Что | Проверка | Если нет |
|---|---|---|
| Python ≥ 3.10 | `python3 --version` | остановиться, сообщить администратору контура |
| python-docx | `python3 -c "import docx"` без ошибок | остановиться (установка вне закрытого контура невозможна) |
| LibreOffice (опционально, только для PDF) | `which soffice` | отчёт будет только в .docx — это допустимо |
| Образец отчёта прошлого квартала (.docx) | файл существует, открывается | остановиться и запросить образец |

## 1. Подготовка рабочего каталога

```
work/                              ← рабочий каталог (создайте)
├── report-style-kit/              ← комплект (скопировать целиком)
├── sample.docx                    ← образец прошлого квартала
└── materials/                     ← ваши исходники (см. шаг 3)
```

Все команды ниже выполняются из каталога `work/report-style-kit/`:
```bash
cd report-style-kit
python3 -c "import docx"   # финальная проверка
```

## 2. Извлечь стиль из образца

```bash
python3 scripts/extract_profile.py --sample ../sample.docx --outdir work/
```

**Создаёт 5 артефактов в `work/`:**

| Файл | Что это |
|---|---|
| `style-profile.json` | машиночитаемый профиль стиля: шрифты, кегли, цвета, стили таблиц, типовые шаблоны таблиц, скелет разделов, микротипографика, глоссарий |
| `template.docx` | пустой шаблон с теми же стилями/темой, что у образца — на нём собирается отчёт |
| `styleguide.draft.md` | черновик правил изложения (тон, структура абзацев, типографика, блоки) |
| `glossary.draft.md` | черновик доменного словаря (термины из образца легальны к употреблению) |
| `slang-blacklist.txt` | список запрещённого агентского сленга (regex по категориям) |

**Проверка:** команда завершилась `exit 0`, в stdout — сводка извлечения; в `work/style-profile.json` есть `title_block`, `table_templates`, `section_blueprint`.

**Если образец «странный»** (нет стилей Heading 1/2 — заголовков в структуре): остановиться и запросить другой образец.

## 3. Подготовить материалы

Соберите в `../materials/`:

| Файл | Содержимое |
|---|---|
| `outline.md` | примерная структура нового отчёта (может быть грубой, по разделам) |
| `notes_draft.md` | черновики, наброски, мысли — в любой форме |
| `numbers.json` (или csv/текст) | числа результатов: метрики, сравнения методов, per-pot данные |
| `charts/*.png` | готовые графики (PNG) |
| `charts/descriptions.md` | описание каждого графика: что изображено, что видно |

**Правило чисел:** в отчёт попадают ТОЛЬКО числа из materials. Числа нет — ставится маркер `$unresolved` (см. шаг 4), выдумывать запрещено.

## 4. Построить content-manifest.json

Напишите `work/content-manifest.json` по схеме (см. `skills/report-content-plan/SKILL.md` — там примеры всех блоков). Структура:

При написании текстов блоков применяйте правила технического писателя: `skills/report-technical-writer/SKILL.md` (тезис первым предложением, конкретные числа с базой сравнения, термины из глоссария, паттерн «что изображено → что видно → вывод» для пояснений графиков).

```json
{
  "meta": {"title": "...", "subtitle": "...", "project": "...", "version": "...", "period": "..."},
  "sections": [
    {"heading": "1. Контекст и постановка задачи", "level": 1,
     "blocks": [ ... ]}
  ]
}
```

**7 типов блоков** (свободного текста не существует):

| Тип | Назначение | Пример из эталона |
|---|---|---|
| `thesis` | тезис-абзац: безлично, 2–5 предложений, тезис первым предложением | «Криолитовое отношение CR = NaF / AlF3 — ключевой параметр…» |
| `lead_in` | жирная метка-строка + текст | «Бизнес-вопрос:» + вопрос |
| `formula` | формула (соберётся курсивом) | `x_pred = x + β_temp_drift · …` |
| `bullets` | маркированный список | выводы, перечни |
| `table` | таблица; заголовки можно взять из шаблона: `"template": "metrics_comparison"` | сводка метрик |
| `figure` | подпись «Рис. N. …» + PNG + пояснение | график + «что изображено → что видно → вывод» |
| `verdict` | вывод с числами (соберётся буллетом) | «…снижение MAE: −8.9 %…; H1 подтверждена.» |

**Правила разворота черновиков:**
1. Разделы outline ↔ `section_blueprint` из профиля (порядок и названия — как в образце).
2. Каждый эксперимент = Цель → Метод → Результаты → Интерпретация; Результаты = таблица по шаблону + числа с контекстом (Δ vs baseline, %, единицы).
3. Каждый график = figure-блок: caption «Рис. N. <что изображено>», explanation «что изображено → что видно → вывод».
4. Термины — только из глоссария (`work/glossary.draft.md`).
5. Тон — безличный: запрещены «я/мы/вы», «давайте», «рассмотрим».
6. Неизвестное число → `"$unresolved"` в тексте блока.
7. Имена шаблонов таблиц (для `"template"`) смотрите в выводе шага 2 (`table_templates` в профиле).

## 5. Прогнать текстовый линт (до сборки)

```bash
python3 scripts/lint_text.py --manifest work/content-manifest.json \
  --profile work/style-profile.json
```

**PASS** (`exit 0`) → шаг 6. **FAIL** (`exit 1`) → читайте `lint_report.txt`: категория, цитата, локатор (`sections[i].blocks[j]`) → исправьте manifest → повторить.

**FAIL-категории:** placeholders (`$unresolved`), first_person, agent_phrases, marketing, office_anglicisms, emoji, markdown_residue, exclamations. Предупреждения (не блокируют): термины вне глоссария, длинный абзац, отклонения типографики.

**Лимит:** максимум 3 итерации правок. Не прошло — СТОП: показать список проблем пользователю. Для `$unresolved`: запросить недостающие числа у пользователя, вписать, перезапустить линт.

## 6. Собрать .docx

```bash
python3 scripts/build_report.py --manifest work/content-manifest.json \
  --profile work/style-profile.json --template work/template.docx \
  -o report.docx
```

**Коды выхода:** 0 — ок; 2 — ошибка в manifest (в сообщении точный путь, чинить manifest, НЕ скрипт); 3 — не найден входной файл; 4 — отсутствуют картинки (список в выводе: добавить PNG или убрать блоки). После правок — вернуться на шаг 5.

## 7. Финальная верификация (текст + визуал)

```bash
python3 scripts/lint_text.py --docx report.docx --blacklist work/slang-blacklist.txt
python3 scripts/lint_visual.py --docx report.docx --profile work/style-profile.json
```

Оба должны дать `exit 0`. Visual FAIL означает несанкционированный стиль — лечится пересборкой через manifest (шаги 4–6), НЕ ручной правкой docx. Лимит итераций — 3, далее СТОП.

## 8. PDF-рендер

```bash
python3 scripts/render_pdf.py --docx report.docx -o .
```

`exit 0` → `report.pdf` готов. `exit 3` (нет soffice) → поставка только .docx, сообщить пользователю.

## 9. Готово — проверить поставку

- `report.docx` открывается; титульный блок, заголовки, таблицы, рисунки на месте
- `report.pdf` (если есть) совпадает по содержанию
- Сообщить пользователю пути к файлам и итог линтов

---

## Типовые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| lint FAIL: agent_phrases | в текст попали «давайте», «мы» и т.п. | переписать безлично, шаг 5 |
| lint FAIL: placeholders | остались `$unresolved` | получить числа у пользователя |
| build exit 2 | структура manifest неверна | читать путь в сообщении об ошибке |
| build exit 4 | PNG не найден | путь к картинке — относительно manifest |
| visual FAIL: недопустимый стиль | manifest вне блоковой грамматики | вернуться к шагу 4 |
| PDF нет (exit 3) | в контуре нет LibreOffice | поставка .docx, сообщить пользователю |
| Образец без заголовков | extract не нашёл Heading | запросить другой образец |

## ЗАПРЕЩЕНО

1. Выдумывать числа, факты, результаты.
2. Править `report.docx` вручную после сборки.
3. Редактировать скрипты, `template.docx`, `style-profile.json`.
4. Обходить линт или отключать категории блэклиста.
5. Английские фразы в русском тексте вне глоссария.
