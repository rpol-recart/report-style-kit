# report-style-kit — дизайн

**Дата:** 2026-09-03
**Статус:** утверждён пользователем (пошагово в диалоге)
**Эталон:** /root/docs_template/CR_Predictor_Report.docx

## Goal

Разработать автономный переносимый комплект скиллов `report-style-kit` для закрытого контура (другая модель, без MCP/интернета): по образцу отчёта прошлого квартала + черновикам/числам/описаниям графиков формировать законченный отчёт в форматах .docx и .pdf, гарантированно сохраняя шрифты, оформление, стиль изложения, доменную лексику и типовые компоненты оформления образца.

## Принцип

«Модель решает ЧТО написано, скрипты гарантируют КАК это выглядит». Вся тяжёлая работа — в детерминированных python-скриптах (python-docx), модель только оркестрирует и наполняет контент.

## Scope

- Каталог report-style-kit/: README.md, skills/ (5 SKILL.md на русском), scripts/ (5 python-скриптов), schemas/ (2 JSON Schema), base/slang-blacklist.txt, tests/
- Конвейер: extract → курирование styleguide/glossary → content-plan (разворот черновиков в content-manifest.json) → lint(manifest) → build(docx) → lint(docx)+lint_visual → render(pdf)
- Двойной выход: report.docx + report.pdf (soffice headless; при отсутствии soffice — docx + явное предупреждение)
- Тестирование в нашей среде: golden-клон на эталоне, round-trip, сленг-фикстуры, синтетический прогон

## Ключевые механизмы

1. Template-наследование: чистый template.docx из образца (тело очищено, стили/тема/нумерация/секции сохранены) — шрифты наследуются 1-в-1
2. Блоковая грамматика content-manifest.json: thesis, lead_in, formula, bullets, table, figure, verdict — свободных абзацев не существует
3. Component-library: автокластеризация таблиц образца по сигнатуре заголовков → именованные table_templates (metrics_comparison, risks_register, key_value_params, per_pot_params, hypotheses_verdicts, version_history и др.) + section_blueprint из дерева заголовков
4. Разворот черновиков: materials/ (outline.md, наброски, числа JSON/CSV, charts/+описания) → готовый текст по правилам: эксперимент = Цель→Метод→Результаты→Интерпретация; график = подпись «Рис. N.» + «что изображено → что видно → вывод»; число = контекст (Δ, %, единицы) и источник
5. Анти-сленг + домен: универсальный блэклист (RU+EN regex-категории) + автоглоссарий образца (всё из образца легально); безличный тон (запрет я/мы/вы), типографика эталона (точка в дробях, −12.2 %, 1–3, «ёлочки», →, ≈, 4×4); линт дважды (manifest → docx), FAIL блокирует конвейер
6. Запрет выдуманных чисел: числа только из materials; маркер $unresolved → lint FAIL → запрос пользователю

## Профиль стиля эталона (для контроля реализации)

US Letter portrait, поля ≈2 см; Calibri 11pt основной / 10pt в таблицах (header-row bold); H1 14pt bold #365F91, H2 13pt bold #4F81BD, H3 bold #4F81BD; таблицы «Light Grid Accent 1»; титульный блок: центрированные Normal-абзацы 20pt bold / 14pt italic / 11pt; подпись «Рис. N. …» над изображением, пояснение под ним; формулы — курсивные Normal-абзацы; жирные lead-in «Бизнес-вопрос:»; ручная нумерация разделов в тексте заголовков.

## Out of scope

- Генерация графиков (PNG поставляются в materials/)
- Изменение эталонного CR_Predictor_Report.docx
- Сверка фактов через lite_rag (закрытый контур — глоссарий только из образца)
