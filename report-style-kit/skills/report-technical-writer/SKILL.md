# Технический писатель: качество прозы блоков манифеста

## Назначение

`report-content-plan` задаёт структуру отчёта — какие блоки и в каком порядке
разворачиваются из черновиков в `content-manifest.json`. Этот скилл отвечает
на вопрос КАК писать текст внутри каждого блока: правила превращают разговорный
набросок в готовую безличную прозу корпоративного стандарта.

Применяется на двух шагах: при построении `content-manifest.json` (шаг 3
конвейера) и при правках после предупреждений линта (`para_length`,
`glossary-warn`).

## Железные правила технического письма

1. **Безличность: действие важнее деятеля.** Никаких «я/мы/вы».
   - Плохо: «Мы применили двухуровневую архитектуру для прогноза».
   - Хорошо: «Применяется двухуровневая архитектура прогноза».
2. **Тезис — первым предложением абзаца.** Далее только раскрытие тезиса,
   без отступлений.
   - Плохо: «Данные собирались месяц. CR — ключевой параметр электролита».
   - Хорошо: «Криолитовое отношение CR — ключевой параметр электролита.
     Далее раскрывается его расчёт по квартальным данным».
3. **Одно предложение — одна мысль.** Длина предложения до ~25 слов.
   - Плохо: «Модель обучалась на квартальных данных, при этом использовались
     признаки, которые были отобраны ранее, а затем всё было пересчитано».
   - Хорошо: «Модель обучалась на квартальных данных. Признаки отобраны на
     предыдущем этапе. Итоговые значения пересчитаны заново».
4. **Конкретность вместо оценок.** Число и единицы вместо «значительно».
   - Плохо: «Достигнуто значительное улучшение качества прогноза».
   - Хорошо: «Снижение MAE на 12.2 % (0.0385 → 0.0338)».
5. **Терминологическая последовательность: один объект — одно имя.** Имя
   берётся из глоссария и не варьируется по ходу документа.
   - Плохо: «модель… моделька… предложенный подход… наш алгоритм» — об одном
     и том же.
   - Хорошо: «модель V9» везде, где речь об этом объекте.
6. **Каждое число — с контекстом.** Δ всегда с явной базой сравнения,
   единицы — при первом упоминании величины.
   - Плохо: «Ошибка снизилась на 12.2 %».
   - Хорошо: «MAE снижен на −12.2 % vs V8a (базовый global-прогноз),
     0.0385 → 0.0338 (среднее по 16 ваннам)».
7. **Без канцелярита.** Глагол вместо отглагольного существительного.
   - Плохо: «Осуществляется использование предвычисленных признаков для
     реализации повышения скорости».
   - Хорошо: «Используются предвычисленные признаки — обучение ускоряется».
8. **Запрет эмоционально-оценочной лексики.** Оценка заменяется критерием.
   - Плохо: «Некоторые ванны показали проблемные результаты».
   - Хорошо: «Ванны с MAE выше медианного значения по корпусу: POT_18,
     POT_20, POT_21».
9. **Каждый символ формулы поясняется при первом появлении.**
   - Плохо: «x_pred = x + β_temp_drift · (ΔT_bath / Δt) · Δt» без расшифровки.
   - Хорошо: «x_pred — прогноз; β_temp_drift — коэффициент дрейфа;
     ΔT_bath — изменение температуры ванны за окно Δt».
10. **Сокращения раскрываются при первом употреблении.**
    - Плохо: «Значения CR держим в целевом диапазоне».
    - Хорошо: «Криолитовое отношение (Cryolite Ratio, CR) держится в целевом
      диапазоне».

## Рецепты по типам блоков

### thesis

Каркас: **определение/факт → механизм/следствие → зачем это читателю**.
2–5 предложений; первое предложение — тезис, второе перечисляет конкретные
следствия.

> «Криолитовое отношение CR = NaF / AlF3 — ключевой параметр электролита
> алюминиевого электролизёра, определяющий ход технологического процесса.
> Отклонение CR от целевого диапазона ведёт к росту расхода фторидов и
> снижению выхода по току. Настоящий отчёт описывает расчёт CR по данным
> за квартал.»

### lead_in

Нужен при смене аспекта внутри раздела: вопрос, риски, параметры. Метка —
короткое существительное с двоеточием («Бизнес-вопрос:», «Ключевые риски:»,
«Модель состояния:»). После метки — самостоятельный текст, раскрывающий её
(не повторяющий метку и не обрывающийся на полуслове).

> label: «Ключевые риски:»
> text: «Дрейф температуры ванны и запаздывание лабораторного анализа CR
> приводят к ошибке прогноза; оба риска закрываются per-pot калибровкой.»

### formula

Текст до формулы задаёт её смысл (например, метка «Модель состояния:»).
Формула — отдельным блоком, без вставок в середину предложения. После формулы —
интерпретация: каждый символ расшифрован, указано, откуда берутся коэффициенты.

> «Модель состояния:» → `x_pred = x + β_temp_drift · (ΔT_bath / Δt) · Δt` →
> «x_pred — прогноз CR; x — последняя оценка; β_temp_drift — коэффициент
> дрейфа, оцениваемый per-pot по истории квартала; ΔT_bath — изменение
> температуры ванны за окно Δt.»

### figure.explanation

Ровно паттерн «что изображено → что видно → вывод» тремя предложениями.
Никаких вводных вроде «на данном графике можно наблюдать».

> «Слева направо: A (Global V8a), B (V9 fixed), C (re-optimization). Видно
> сжатие облака к диагонали при переходе A → C. Это подтверждает устойчивость
> улучшения per-pot оптимизации.»

### verdict

Каркас: **число + сравнение → вердикт → следствие для производства**.
Только факты из экспериментов, без новых.

> «Per-pot оптимизация KF (V9) даёт устойчивое снижение MAE: −8.9 % в среднем
> по walk-forward относительно глобального baseline V8a; H1 подтверждена.
> Модель передаётся в производственный контур ежеквартального пересчёта CR.»

### bullets

Параллельная структура пунктов: все начинаются однотипно — с существительного
или глагола действия. Один пункт — один факт. Нумерация выводов — только когда
важен порядок (иначе маркеры).

> - «Factor_rz: rolling z-score электрического Factor c EWM-сглаживанием.»
> - «Fluor_lag84: интегрированная масса AlF3 (кг) в окне 24 ч с лагом 84 ч.»
> - «Bath_Temp: точечное значение температуры ванны (порог свежести ≤ 48 ч).»

### table

Единицы измерения — в заголовке колонки («Avg MAE (CR)»), в ячейках только
значения без повторения единиц. Пустая ячейка = «—», не пустая строка и не
«нет данных».

> | Метод | Avg MAE | Δ vs baseline | Pots улучшились |
> |---|---|---|---|
> | V8a (global baseline) | 0.0385 | — | — |
> | V9 (per-pot KF) | 0.0338 | −12.2 % | 16 из 16 |

## Работа с черновиками

Разговорный набросок → готовый текст (типовые трансформации):

| Разговорный набросок | Готовый текст |
|---|---|
| «мы улучшили метрику прикольным способом» | «Per-pot оптимизация снижает avg MAE на 12.2 % (0.0385 → 0.0338) относительно глобального baseline V8a» |
| «график показывает что точки лежат примерно на диагонали» | figure.explanation по паттерну: «Слева направо: A (Global V8a), B (V9 fixed), C (re-optimization). Видно сжатие облака к диагонали при переходе A → C. Это подтверждает устойчивость улучшения per-pot оптимизации.» |
| «были некоторые проблемы с несколькими ваннами» | «Три ванны (POT_18, POT_20, POT_21) показывают MAE выше медианного значения по корпусу (см. Known Unknown U-02)» |
| «модель обучалась долго но потом стало быстрее» | «Время обучения снижено с ~3 ч (E1) до 68 с (E2) за счёт предвычисления z-cr и drift_rate per-pot» |

## Числа и типографика

Следовать `profile.microtypography` из `work/style-profile.json`:

- десятичная точка (0.0338, не 0,0338);
- типографский минус в Δ: «−12.2 %» — с пробелом перед %;
- диапазоны через короткое тире без пробелов: 1–3;
- «≈» для оценочных величин («≈ 3 ч»);
- «×» для размерностей сеток и матриц («сетка 16 × 3»).

Проценты изменений считаются от явной базы, база указывается рядом:
«−12.2 % vs V8a». Процент без базы не проходит.

## Самопроверка перед линтом

- [ ] Нет «я/мы/вы» и обращений к читателю («давайте», «рассмотрим»).
- [ ] Каждый абзац начинается с тезиса.
- [ ] Каждое число имеет источник в `materials/` и явную базу сравнения.
- [ ] Термины — из глоссария и написаны единообразно по всему документу.
- [ ] Каждая формула сопровождена расшифровкой символов и источником коэффициентов.
- [ ] Explanation каждого графика — по паттерну «что изображено → что видно → вывод» (3 предложения).
- [ ] Нет оценочной лексики («успешный», «проблемный», «прикольный», «очевидно»).
- [ ] Абзацы — 2–5 предложений; предложения до ~25 слов.

## Типовые ошибки

| Ошибка | Пример | Исправление |
|---|---|---|
| Дублирование очевидного из таблиц | «Как видно из таблицы, V9 имеет MAE 0.0338» | Таблица говорит сама за себя; текст — только вывод: «V9 снижает MAE на −12.2 % vs V8a» |
| «очевидно, что…» | «Очевидно, что пер-пот подход лучше» | Удалить вводность; оставить факт с числом и базой |
| Будущее время для сделанного | «В этом разделе будет показано снижение MAE» | Прошедшее/настоящее: «В разделе показано снижение MAE на −8.9 %» |
| Вопрос в thesis | «Что такое CR и зачем он нужен?» | Утвердительное определение: «CR — криолитовое отношение, ключевой параметр электролита» |
| Сленг | «фидбек», «чекнуть», «апдейт» | Нейтральный русский: «отзыв», «проверить», «обновить» |
| Число без базы | «Ошибка снизилась на 12.2 %» | База явно: «MAE снижен на −12.2 % vs V8a» |
