# Оркестратор конвейера отчёта

## Назначение

Входная точка комплекта. Проводит полный конвейер 0–7: от образца отчёта прошлого
квартала и материалов (`materials/`) до готовых `отчёт.docx` и `отчёт.pdf`,
гарантированно воспроизводя стиль образца. Модель решает, ЧТО написано;
скрипты гарантируют, КАК это выглядит. Все команды выполняются в текущем рабочем
каталоге конвейера — все пути относительные.

## Пререквизиты

Перед любым шагом проверь окружение:

```bash
python3 -c "import docx"
```

- Команда завершилась ошибкой (`ModuleNotFoundError`) → **СТОП**. Сообщи пользователю:
  «python-docx не установлен, конвейер невозможен», и прекрати работу.
- PDF (шаг 7) требует LibreOffice. Проверка: `command -v soffice`. Если не найден —
  это **не блокер**: шаги 0–6 выполняются полностью, на шаге 7 скрипт сам сообщит
  «PDF недоступен: soffice не найден», и отчёт останется только в .docx.

## Входы

| Вход | Что это |
|---|---|
| образец отчёта | `.docx` отчёта прошлого квартала (эталон стиля) |
| `materials/outline.md` | план нового отчёта: разделы и порядок |
| `materials/*.md` | черновики/наброски текста по разделам |
| `materials/*.json`, `materials/*.csv` | числа: метрики, сравнения, таблицы |
| `materials/charts/*.png` | готовые графики + описания (что изображено, что видно) |

Числа и факты берутся ТОЛЬКО из `materials/`. Чего нет в материалах — того не существует.

## Конвейер 0–7

### Шаг 0 — проверки

- Убедись, что образец `.docx` существует и открывается.
- Убедись, что `materials/` содержит хотя бы `outline.md` и числа.
- Пререквизиты из раздела выше.

### Шаг 1 — извлечение стиля

```bash
python3 scripts/extract_profile.py --sample образец.docx --outdir work/
```

Ожидаемые артефакты: `work/style-profile.json`, `work/template.docx`,
`work/styleguide.draft.md`, `work/glossary.draft.md`, `work/slang-blacklist.txt`.
Подробнее — `skills/report-style-extract/SKILL.md`.

### Шаг 2 — курирование стиля

Прочитай `work/styleguide.draft.md` и `work/glossary.draft.md` глазами:

- сверь `title_block` профиля с титульной страницей образца визуально;
- просмотри шаблоны таблиц: в styleguide переименуй безликие `table_template_N`
  в осмысленные имена (имена в `style-profile.json` не меняются);
- выкини из глоссария мусорные токены.

Сохрани выкуренные версии как `work/styleguide.md` и `work/glossary.md`.

### Шаг 3 — план содержимого

По правилам `skills/report-content-plan/SKILL.md` разверни `materials/` в
`content-manifest.json`: разделы по `section_blueprint` профиля, черновики —
в типизированные блоки, числа — только из материалов.
При написании текстов блоков ОБЯЗАТЕЛЬНО применять
`skills/report-technical-writer/SKILL.md` (качество прозы) вместе с
report-content-plan (структура).

Ожидаемый артефакт: `content-manifest.json`.

### Шаг 4 — линт манифеста

```bash
python3 scripts/lint_text.py --manifest content-manifest.json --profile work/style-profile.json
```

- `PASS` (код 0) → шаг 5.
- `FAIL` (код 1) → исправь `content-manifest.json` по категориям из отчёта
  и повтори команду. При правках предупреждений `para_length`/`glossary` —
  перечитай правила технического писателя
  (`skills/report-technical-writer/SKILL.md`). **Максимум 3 итерации**; после третьего FAIL — СТОП и вопрос
  пользователю (процитируй категории нарушений).

### Шаг 5 — сборка docx

```bash
python3 scripts/build_report.py --manifest content-manifest.json --profile work/style-profile.json --template work/template.docx -o отчёт.docx
```

Ожидаемый артефакт: `отчёт.docx`. Код 2 — ошибка манифеста (исправляй манифест,
не скрипт), код 4 — не найдены файлы картинок (добавь файлы или убери блоки).

### Шаг 6 — линт собранного отчёта

```bash
python3 scripts/lint_text.py --docx отчёт.docx --blacklist work/slang-blacklist.txt
python3 scripts/lint_visual.py --docx отчёт.docx --profile work/style-profile.json
```

- Оба `PASS` → шаг 7.
- `FAIL` → цикл правок: исправь манифест → повтори шаг 5 (сборка) → повтори
  оба линта этого шага. **Максимум 3 цикла**; после третьего — СТОП и вопрос
  пользователю. Не редактируй `отчёт.docx` руками — только через пересборку.

### Шаг 7 — рендер PDF

```bash
python3 scripts/render_pdf.py --docx отчёт.docx -o out/
```

Ожидаемый артефакт: `out/отчёт.pdf` (требует soffice; при его отсутствии — см. Пререквизиты).

## STOP-условия

| Ситуация | Действие |
|---|---|
| Число отсутствует в `materials/` | Вставь в манифест `"$unresolved"` на место числа и продолжай. ПОСЛЕ первого FAIL линта (категория placeholders) — остановись и спроси пользователя, откуда взять число. |
| График отсутствует в `materials/charts/` | Не выдумывать и не рисовать. Спроси пользователя: прислать PNG или убрать figure-блок. |
| В образце нет стилей Heading 1/2 | СТОП на шаге 1: сообщи пользователю, что образец не годится как эталон стиля. |
| 3 FAIL подряд на любом шаге линта | СТОП и вопрос пользователю с цитатами нарушений. |

## ЗАПРЕЩЕНО

- Выдумывать числа, факты, названия экспериментов, графики.
- Менять скрипты `scripts/`, схему `work/template.docx` или `work/style-profile.json`.
- Писать свободный текст в обход блоковой грамматики манифеста (7 типов блоков).
- Обходить линт или править собранный `.docx` руками.
- Вставлять английские фразы в русский текст вне глоссария образца.
