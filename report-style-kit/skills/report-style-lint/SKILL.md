# Двухстадийный линт: текст и оформление

## Триггер

Выполняется дважды за конвейер: после content-plan (стадия 1 — манифест) и после
build (стадия 2 — собранный .docx). FAIL любой стадии блокирует конвейер.

## Стадия 1 — линт манифеста (после content-plan)

```bash
python3 scripts/lint_text.py --manifest content-manifest.json --profile work/style-profile.json
```

Код 0 — PASS (предупреждения допустимы), 1 — FAIL. Отчёт печатается в stdout
и сохраняется в `lint_report.txt`.

## Стадия 2 — линт собранного отчёта (после build)

```bash
python3 scripts/lint_text.py --docx отчёт.docx --blacklist work/slang-blacklist.txt
python3 scripts/lint_visual.py --docx отчёт.docx --profile work/style-profile.json
```

`lint_visual` пишет `visual_report.txt`: стили абзацев, шрифты/кегли ролей,
стиль таблиц, титульный блок, поля страницы — всё сверяется с профилем образца.

## Категории

**FAIL (блокируют, код 1):**

| Категория | Что ловит |
|---|---|
| placeholders | `$unresolved`, `TBD`, `TODO`, `FIXME`, `???` |
| first_person | «я», «мы», «нас», «ваш» и т.п. |
| agent_phrases | «давайте», «рассмотрим», «итак», «супер»… |
| marketing | «инновационный», «уникальный», «лучшее решение»… |
| office_anglicisms | «фидбек», «деливери», «чекнуть», «апдейтнуть»… |
| emoji | эмодзи и пиктограммы |
| markdown_residue | `**`, `#` в начале строки, обратные кавычки, `\|---` |
| exclamations | восклицательный знак `!` |

**Предупреждения (не блокируют):** glossary-warn (латинский токен вне глоссария),
para_length (абзац длиннее 5 предложений), typography (запятая в дробях вместо
точки, ASCII-дефис вместо минуса U+2212, прямые кавычки вместо «ёлочек»).

## Правило цикла

1. FAIL по текстовым категориям → исправь манифест/тексты → повтори линт.
2. **Максимум 3 итерации.** После третьего FAIL — СТОП и вопрос пользователю
   с цитатами нарушений из отчёта.
3. **Visual FAIL почти всегда означает, что манифест использует
   несанкционированный стиль или шрифт.** Лечится пересборкой: исправь манифест
   → `build_report.py` → повтори линт. Не редактируй собранный `.docx` руками —
   правка в обход сборки сломает соответствие профилю и будет потеряна при
   следующей пересборке.
